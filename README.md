# 乒乓球短视频智能分析系统

## 产品 / 技术说明（分析原理 + 当前实现）

---

## 一、产品定位（一句话）

> 一个面向初学者与进阶用户的 **短视频动作纠错教练系统**：
> 用户上传 3–12 秒乒乓球视频 → 系统自动抽取关键画面 → 大模型基于动作过程进行推理 → 输出 **3 个关键问题 + 3 个可执行改进训练**。

---

## 二、核心设计理念（非常关键）

### 我们不做什么

* 不做整局长视频统计（胜率、跑动距离）
* 不做骨骼点位/3D 姿态重建（第一版）
* 不追求运动科学级别的精度

### 我们真正解决什么

* **单个动作 / 单次失误的快速复盘**
* **让用户“知道自己哪里错、该怎么练”**
* **结果稳定、可理解、像真人教练**

---

## 三、分析原理总览（核心）

### 本质原理

> **动作分析 ≠ 识别一帧画面**
> **动作分析 = 时间序列中的变化 + 上下文推理**

系统采用的是一种 **「轻视觉 + 强推理」** 的分析范式：

* 用 **时间有序的关键画面** 表示动作过程
* 用 **分段（segment）** 表示动作阶段
* 用 **大语言模型** 承载教练经验与因果推理
* 用 **强结构约束** 保证输出稳定、不胡说

---

## 四、分析流程（从视频到结果）

### 1️⃣ 视频 → 时间序列关键画面

* 输入：3–12 秒手机拍摄视频（mp4 / mov）
* 抽帧策略：

  * 固定时间间隔（0.3–0.5s）
  * 最少 6 张，最多 12 张（UI 可控上限）
  * 每张帧都带时间戳（t = xx.xx s）

> 作用：
> 用少量画面，覆盖「准备 → 启动 → 出手 → 触球 → 结果」

---

### 2️⃣ 时间轴 → 分段（Segment）

* 将视频按时间均分为 N 段（通常 6–8 段）
* 每段有：

  * `start_time / end_time`
  * 属于该段的关键帧集合
* 每个分段都必须被分析与点评

> 作用：
> 强制模型**像教练一样“看过程”**，而不是给整体泛化评价。

---

### 3️⃣ 分段聚合 → 结构化输入给大模型

大模型**并不直接看视频或图片**，而是接收：

* **按分段聚合的关键帧摘要**

  ```
  Segment 2 (1.8s–2.6s):
  - Frame 42 at 1.92s
  - Frame 51 at 2.30s
  ```
* **特征摘要（基础统计）**

  * 视频时长、帧数、分段数
* **用户上下文**

  * 失误类型（如：扣杀失败）
  * 站位（近台/中远台）
  * 左右手
  * 用户自述一句话（如：“侧身总慢半拍”）

---

### 4️⃣ 大模型分析（核心智能发生处）

大模型被严格约束为 **“乒乓球教练角色”**，并必须：

#### 输出结构（强制 JSON）

* **3 个主要问题**

  * 动作点（title）
  * 画面证据（引用 Frame X at Ts）
  * 影响结果（为什么会失误）
* **3 个改进措施**

  * 训练方法（drills）
  * 训练量（reps）
  * 关键口令（checkpoints）
  * 常见错误（cautions）
* **逐段点评**

  * 每一段必须点评
  * 每一段必须至少引用 1 个该段的 Frame 证据

> 如果不满足结构或证据要求 → 输出视为不合格 → 自动兜底（mock / 重试）

---

## 五、为什么“不做骨骼点”也能有效？

### 原因不是“做不了”，而是“没必要（第一版）”

* 初学者最需要的是：

  * **动作节奏**
  * **是否到位**
  * **是否抢点 / 慢半拍**
* 这些问题：

  * 人类教练主要靠**时间过程 + 画面变化**判断
  * 而不是精确角度数值

### 当前系统的优势

* 减少视觉误判
* 降低成本与延迟
* 更稳定、更少胡说
* 更适合 MVP 与真实用户验证

> 后续可在 **features_summary** 中逐步加入姿态指标，不破坏整体架构。

---

## 六、输出为什么“像教练而不是废话”？

因为系统做了 **三层强约束**：

### 1️⃣ 结构约束

* 固定 3 问题 + 3 措施
* 字段缺失即失败

### 2️⃣ 内容约束

* 问题必须包含「动作点 + 证据 + 影响」
* 措施必须包含「方法 + 训练量 + 口令 + 错误」

### 3️⃣ 证据约束

* 每段点评必须引用 **本段 Frame X at Ts**
* 禁止跨段乱引用

👉 **大模型不是“自由发挥”，而是在一个高度受控的教练推理空间中工作。**

## 八、可演进性（不会推倒重来）

当前架构是 **“专业系统的下限版本”**：

* 将来可加：

  * 姿态/骨架特征（仅增强 features_summary）
  * 发球/接发专项模板
  * 长期个人问题统计
* UI / Agent / Pipeline **不需要重写**

## 九、总结一句话（对外用）

> 本系统不是在“识别动作”，
> 而是在 **用时间有序的视觉证据，驱动大模型进行教练级动作推理**，
> 以最低成本、最高稳定性，解决初学者最真实的训练痛点。
